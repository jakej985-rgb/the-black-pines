# Palette's UX & Accessibility Journal

## 2026-11-10 - Keyboard focus parity on procedural UI buttons
**Learning:** Procedurally generated UI buttons in Godot controls (such as item list entries or crafting recipe rows) frequently only connect to `mouse_entered` for details inspection. This completely breaks accessibility for keyboard navigation (Tab / UI focus directional keys), leaving keyboard-only players unable to view descriptions or inspect item stats. In addition, setting `tooltip_text` on dynamic buttons provides native desktop hover tooltips and screen-reader hints, including explanatory disabled states on buttons like "Craft".
**Action:** When dynamically instantiating UI `Button` instances that reveal details on hover, always connect both `mouse_entered` and `focus_entered` to the inspector callback and populate `tooltip_text` (including disabled context on action buttons).

## 2026-11-11 - Initial keyboard focus and mutual dialog switching in Godot UI
**Learning:** When Godot modal UI dialogs (such as Inventory or Journal) are opened via key actions, no child control node automatically receives focus by default, causing directional keyboard/gamepad navigation to fail until the user performs a mouse click. Furthermore, independent `_unhandled_input` handlers across dialogs cause them to open simultaneously on top of one another when switching keys (`Tab` and `J`) are pressed.
**Action:** Explicitly call `grab_focus()` on the first interactive item button upon opening a dialog to ensure immediate keyboard accessibility and auto-population of detail labels. Handle cross-dialog hotkeys by closing active dialogs and allowing unhandled events to propagate to sibling dialogs smoothly.

## 2026-11-12 - Tab cycling shortcuts and category-aware focus retention in TabContainer dialogs
**Learning:** In Godot 4 `TabContainer` interfaces, keyboard navigation is disrupted when navigating between tabs because TabContainer does not provide default bumper/cycling keybinds (`Q`/`E`), and switching tabs leaves focus stranded on elements belonging to inactive tab pages or drops focus entirely. Connecting `tab_changed` to an active-tab focus handler guarantees keyboard and gamepad accessibility stays synchronized with the visible category.
**Action:** Provide `Q`/`E` tab cycling in modal dialog `_unhandled_input` handlers, connect `tab_container.tab_changed` to focus the first interactive item or active tab bar within the selected category, and update footer hints to explicitly guide players.

## 2026-11-13 - Dynamic reticle focus state and modal occlusion hiding in survival horror HUDs
**Learning:** In first-person games with sparse, minimalist HUDs, keeping the reticle static forces players to read peripheral prompt text to verify interactability. Providing micro-feedback directly on the crosshair (subtle expansion and warm chromatic tint when an interactable enters raycast focus) creates instant, non-verbal targeting confirmation. Furthermore, leaving the center crosshair rendered while modal dialogs (inspection sheets, inventory, journal) are active produces visual obstruction over readable text and breaks immersive diegesis.
**Action:** Bind interactable prompt state changes to reticle modulate/dimension properties, and hide the crosshair whenever full-screen or centered modal overlays are active.

## 2026-11-14 - Modal backdrop dimming and mutual exclusivity for inspection panels
**Learning:** Clue inspection popups that lack a full-screen backdrop dimming scrim suffer severe legibility problems in dynamic 3D environments, as varying background luminance (flashlight cones, fog, moonlight) reduces contrast against small text. In addition, without mutual modal exclusivity, inspecting a clue while the inventory or journal is open leads to colliding UI layers and conflicting dismiss hotkeys.
**Action:** Always place an atmospheric dimming scrim behind modal inspection dialogs, ensure opening an inspection closes active dialogs, and allow pressing dialog hotkeys (`Tab`/`J`) to dismiss the active inspection panel seamlessly.

## 2026-11-15 - Tactile acoustic confirmation for modal states and tab transitions
**Learning:** In minimalist survival horror user interfaces with dark, translucent overlays, silent transitions during dialog toggle actions (`Tab`, `J`, `Esc`) and tab page cycling (`Q`/`E`) make state changes feel unresponsive and disconnected. Adding subtle non-diegetic click feedback (`AudioDirector.instance.play_click()`) on modal open, close, and tab index switching provides vital sensory confirmation that an input has successfully taken effect, reinforcing accessibility for both keyboard and gamepad navigation.
**Action:** Always pair modal dialog open/close lifecycle methods and tab cycling input handlers with procedural tactile audio feedback cues.

## 2026-11-16 - Focus retention on empty tab categories and craft status feedback parity
**Learning:** When switching to an empty TabContainer category, attempting to grab focus on list items fails silently, leaving keyboard/controller focus stranded on hidden controls in inactive tabs or leaving generic "Hover over an item" prompts. Furthermore, when crafting items, separating info buttons from action buttons without linking hover/focus states leaves players without clear visual feedback explaining why an action is available or disabled.
**Action:** Always fallback keyboard focus to the active `tab_bar` and provide explicit empty-state messaging when list containers have no items, and bind hover/focus inspect callbacks to both info rows and action buttons to keep detail panels synchronized with real-time crafting status.

## 2026-11-17 - Inspection modal mouse-capture lifecycle, multi-key dismissal, and acoustic feedback
**Learning:** In first-person games where inspecting narrative documents or environmental clues opens an in-world panel, omitting mouse cursor uncapture (`Input.MOUSE_MODE_VISIBLE`) traps players in raw input states, and failing to restore `Input.MOUSE_MODE_CAPTURED` upon dismissal leaves the camera stranded. Furthermore, restricting dismissal solely to `[E]` or `[Esc]` frustrates players expecting standard prompt confirmation keys (`Space` / `Enter`), and silent modal transitions lack physical presence.
**Action:** Always synchronize mouse visibility with inspection modal lifecycles (only capturing when all modals are dismissed), support both default action keys (`Space`, `Enter`, `E`, `Esc`), provide clear button prompt hints, and trigger tactile acoustic click feedback on display and close.

## 2026-11-18 - Universal mouse mode capture guards across modal dialogues
**Learning:** When multiple modal overlays coexist (such as Inventory, Journal, and Clue Inspection dialogs), dismissing one dialog while another remains open causes premature mouse recapture (`Input.MOUSE_MODE_CAPTURED`) if dismissal routines capture the cursor unconditionally. This suddenly hides the cursor while UI buttons and tabs are still visible, stranding pointer navigation and confusing the player.
**Action:** Always guard `Input.set_mouse_mode(Input.MOUSE_MODE_CAPTURED)` in modal dismiss/close routines by checking whether sibling modals or inspection overlays remain visible, only recapturing the cursor when all modal controls are fully closed.

## 2026-11-19 - Keyboard focus parity and card navigation in field journal dialogues
**Learning:** In field notebook and journal UI systems where cards or logs are displayed in scrollable lists, leaving instantiated cards as passive non-focusable panels (`FOCUS_NONE`) locks keyboard and controller players out of navigating entries. Even when the active tab bar gains initial focus, players cannot tab into or highlight individual objectives or clues. Configuring `focus_mode = Control.FOCUS_ALL` on entry cards and updating tab-focus handlers to prioritize the first focusable entry child with fallback to `tab_bar.grab_focus()` creates seamless keyboard accessibility across filled and empty tab states.
**Action:** Always set `focus_mode = Control.FOCUS_ALL` on procedurally generated journal and evidence cards, and have tab-focus routines target the first focusable child before falling back to the active tab bar.
